# 6T SRAM Bitcell: Design, Verification and Characterization (180 nm CMOS)

Full-custom design and characterization of a 6-transistor (6T) SRAM bitcell using the **gpdk180 (180 nm CMOS)** process and the Cadence toolchain. The project covers the complete design flow: schematic design, physical layout, DRC/LVS verification, functional testing, static noise margin (SNM), timing characterization, leakage analysis, PVT corner analysis, Monte Carlo analysis, post-layout verification, and GDSII export.

## Working with Existing SRAM Designs

If you want to use or modify the existing SRAM circuits, follow the procedure below.

1. Navigate to the `Cadence Files/` directory in the repository.
2. Copy the entire `KAnth` folder.
3. Paste the copied `KAnth` folder directly into your main Cadence working directory, alongside your existing Cadence project folders.
4. Open Cadence Virtuoso and launch Library Manager.
5. Check whether the `SRAM_6T` library and its cellviews are accessible.
6. Open the required schematic, testbench, or layout and continue with your own simulations or modifications.

**Why use this method?**

The folder contains the existing SRAM design library, cellviews, testbenches, and saved simulation setups. Reusing this structure can save time compared with rebuilding the circuits and testbenches from scratch.

**Important:** This shortcut works only when your main `cds.lib` already defines the required library or uses a compatible library-discovery mechanism. If the library is not recognized, update the existing library definition to point to the copied `SRAM_6T` directory. You do not need to create a separate `cds.lib` file if your main setup can correctly register the library.

Before running simulations, verify that the gpdk180 technology libraries, model files, simulator settings, and any required extraction technology files are configured correctly.

## Design Overview

### 6T SRAM Cell Topology

The SRAM bitcell uses six MOSFETs arranged as two cross-coupled CMOS inverters and two NMOS access transistors.

- **Two PMOS transistors:** Pull-up devices that connect the internal storage nodes to VDD.
- **Two NMOS transistors:** Pull-down drivers that connect the storage nodes to ground.
- **Two NMOS access transistors:** Connect the storage nodes to the complementary bitlines when the wordline is asserted.

The cross-coupled inverters provide two stable storage states. The wordline controls access to the cell through the bitlines.

### Transistor Sizing

| Transistor | Role | Width (W) | Length (L) |
|---|---|---:|---:|
| PM0, PM1 | Pull-up PMOS | 2 µm | 180 nm |
| NM2, NM3 | Pull-down NMOS drivers | 2 µm | 180 nm |
| NM0, NM1 | Access NMOS | 1 µm | 180 nm |

The access transistors are smaller than the pull-down drivers to improve read stability while retaining sufficient write ability.

The reported sizing ratios are:

- **Cell ratio (CR):** Driver NMOS width / access NMOS width = 2/1 = 2.
- **Pull-up ratio (PR):** Access NMOS width / pull-up PMOS width = 1/2 = 0.5.

These are width-based ratios for the stated design. Actual stability and writeability also depend on device characteristics, supply voltage, operating conditions, and parasitic effects.

### Symbol and Pin Configuration

The SRAM bitcell is wrapped in a reusable symbol used by the testbenches.

| Pin | Function |
|---|---|
| `Word` | Wordline control |
| `Vdd` | Positive supply |
| `Bl` | Bitline |
| `Blbar` | Complementary bitline |
| `Q` | First internal storage node |
| `Qb` | Complementary internal storage node |
| `Gnd` | Ground |

## Testbench Design

Three main testbenches are included.

| Testbench | Purpose | Analysis |
|---|---|---|
| `sram_schematic_tb` | Functional verification of hold, write-1, read, and write-0; pre-layout/post-layout timing comparison | Transient, 12 ns |
| `SRAM_SNM` | Hold, read, and write SNM, supplementary power analysis, PVT analysis, and Monte Carlo analysis | DC sweep and ADE XL analyses |
| `SRAM_delay` | Write-1, write-0, and read delay measurements | Transient, 15 ns |

### Functional Verification

The functional testbench verifies that the bitcell can:

1. Retain its stored value when the wordline is low.
2. Write logic 1 through the bitlines.
3. Read the stored value.
4. Write logic 0 through the bitlines.

The complementary bitlines are driven with opposite values during writing. During a read, both bitlines are precharged or driven high in the documented testbench setup, and the stored state influences the bitline response.

### SNM Testbench Settings

The documented operating conditions are:

| Mode | Wordline | Bl | Blbar |
|---|---:|---:|---:|
| Hold | 0 V | 1.8 V | 1.8 V |
| Read | 1.8 V | 1.8 V | 1.8 V |
| Write 0 | 1.8 V | 0 V | 1.8 V |

The SNM testbench uses a swept DC source (`V4`, swept from 0 to 1.8 V) to obtain the required transfer characteristics.

> The sweep-based setup should be interpreted according to its exact circuit connections. For a conventional butterfly-curve SNM measurement, both inverter voltage-transfer characteristics must be constructed and the maximum inscribed square determined. A single swept-node curve alone is not sufficient to establish a complete SNM value.

### Delay Testbench Settings

| Case | Bl1 | Bl2 | Blb1 | Blb2 | Initial Conditions |
|---|---:|---:|---:|---:|---|
| Write 1 | 0 V | 1.8 V | 1.8 V | 0 V | Q = 0 V, Qb = 1.8 V |
| Write 0 | 1.8 V | 0 V | 0 V | 1.8 V | Q = 1.8 V, Qb = 0 V |
| Read | 0 V | 1.8 V | 0 V | 1.8 V | Q = 1.8 V, Qb = 0 V |

Initial conditions place the bistable cell in the state opposite to the value being written, ensuring that a genuine state transition occurs during the write operation.

For delay measurement, the Calculator's `delay()` function is used with the relevant input and output waveforms. The documented setup uses `/net2` for the wordline and `/Q` for the storage node, with a 0.9 V threshold and a rising-edge crossing.

**Measurement caution:** A wordline-to-storage-node delay is not necessarily the conventional SRAM read access time or write time. Standard access-time and write-time measurements should use explicitly defined timing references, such as wordline assertion, bitline development, sense-amplifier output, or storage-node transition. Interpret the reported delays using the exact measurement definitions in the simulation report.

## How to Reproduce the Design

### 1. Prepare the Cadence Environment

- Install or access a compatible Cadence Virtuoso environment.
- Configure the licensed gpdk180 PDK and its technology files.
- Confirm that Spectre, Assura, and Quantus QRC are available if you intend to reproduce the complete flow.

### 2. Load the Existing SRAM Library

- Copy `Cadence Files/KAnth/` into your Cadence main working directory.
- Open Virtuoso and check Library Manager.
- Confirm that the `SRAM_6T` library is registered and its cellviews are accessible.
- If necessary, update the existing `cds.lib` with the correct absolute or relative library path.

The original documented path is:

```text
/home/vlsilab/KAnth/SRAM/SRAM_6T
```

Replace this path with the actual location on your machine if your configuration requires it.

### 3. Verify the Schematic

Open the `sram_schematic` cell and check:

- Transistor connectivity and sizing.
- Supply and ground connections.
- Cross-coupled inverter connections.
- Access transistor connections to `Word`, `Bl`, and `Blbar`.
- Pin names and symbol connectivity.

Run a basic transient simulation before proceeding to layout verification.

### 4. Run DRC and LVS

Use Cadence Assura to perform:

- **DRC:** Verify that the layout satisfies the applicable design rules.
- **LVS:** Verify that the extracted layout connectivity matches the intended schematic.

The documented results show clean DRC and LVS with zero mismatches.

### 5. Run Parasitic Extraction

Use Quantus QRC to extract parasitic resistance and capacitance from the layout.

Confirm that the extraction produces the `av_extracted` view and that the extracted view is usable in simulation.

### 6. Run Functional Simulations

Open `sram_schematic_tb` and execute the transient testbench.

Check the hold, write-1, read, and write-0 phases. Confirm that the storage nodes retain complementary logic levels and that write operations change the stored state as intended.

### 7. Run SNM Analysis

Open `SRAM_SNM` and load the documented DC sweep configuration.

Review the hold, read, and write characteristics. For rigorous numerical SNM reporting, use the appropriate butterfly curves and maximum-inscribed-square method.

### 8. Run Delay Analysis

Open `SRAM_delay` and configure the transient analysis for 15 ns.

Set the documented initial conditions and bitline waveforms for each test. Use the Calculator to measure the specified threshold crossings.

### 9. Run PVT Corner Analysis

Open the ADE XL setup associated with `SRAM_SNM`.

Use the documented temperature and supply-voltage values:

- Temperatures: 27°C, -40°C, and 125°C.
- Supply voltages: 1.8 V, 1.62 V, and 1.98 V.
- Process corners: FF, FS, SF, and SS.

The project summary reports approximately 45 simulation runs. This is not the full Cartesian product of four process corners, three temperatures, and three supply voltages, which would contain 36 combinations before any additional runs. Check the saved ADE XL setup for the exact run count and combinations.

### 10. Run Monte Carlo Analysis

Open the ADE XL Monte Carlo setup.

- Select Monte Carlo sampling.
- Configure 200 runs.
- Select the `stat` model section, if supported by the installed PDK and model configuration.
- Run the simulation and inspect the distribution, mean, standard deviation, and failure count.

The reported result is 100% observed yield over 200 runs. This means no failures were observed in the simulated sample; it does not establish a guaranteed 100% manufacturing yield.

### 11. Run Post-layout Simulation

Create or open a config view that binds the SRAM cell to `av_extracted`.

Load the saved pre-layout ADE state, rerun the analysis with the extracted view, and save the results in the `post_layout` state.

Compare the pre-layout and post-layout waveforms and delay measurements.

### 12. Export the Layout

Use the appropriate Cadence stream-out utility to export the layout in the required format.

Verify the output format and export log before distributing the file. Do not assume that a file with a `.gds` extension necessarily contains GDSII data.

## Results and Characterization

### 1. Functional Verification

The transient simulations cover hold, write-1, read, and write-0 operations.

The waveforms are used to check correct state storage and switching behavior.

### 2. Static Noise Margin

Hold, read, and write stability are investigated through the documented SNM testbench.

The report includes the associated characteristic curves. Numeric SNM values should be interpreted according to the measurement method used.

### 3. Write and Read Timing

The reported delays are:

| Operation | Delay |
|---|---:|
| Write 1 | 69.93 ps |
| Write 0 | 40.25 ps |
| Read | 26.80 ps |

The post-layout timing comparison reports:

| Measurement | Pre-layout | Post-layout | Change |
|---|---:|---:|---:|
| tprf | 8.040 ns | 8.049 ns | +0.11% |
| tpfr | 1.990 ns | 2.139 ns | +7.5% |

The pre-layout and post-layout results are based on the saved testbench and measurement definitions. The two timing groups should not be directly equated without confirming that they use the same transitions, nodes, and threshold definitions.

### 4. Leakage and Supplementary Power Analysis

The documented hold leakage is:

- Current: 21.29 pA.
- Power: 38.3 pW.

These values correspond to a specified fixed operating point.

A separate supplementary power sweep reports:

- Peak power: approximately 741.56 µW.
- Average power: approximately 267.208 µW across the sweep.

The power sweep drives the cell through a switching region and includes substantial crowbar current. It must not be interpreted as idle leakage power.

### 5. PVT Analysis

The PVT analysis examines the circuit's behavior under process, voltage, and temperature variations.

The documented simulations report no observed failures across the executed runs. The exact combinations should be verified from the saved ADE XL setup and results.

### 6. Monte Carlo Analysis

The Monte Carlo analysis uses 200 runs and reports:

| Metric | Result |
|---|---:|
| Number of runs | 200 |
| Observed yield | 100% |
| Mean | 153.6 mV |
| Standard deviation | 32.56 mV |

The interpretation of the mean and standard deviation depends on the exact measured quantity and statistical expression configured in ADE XL. Consult the report and saved expressions before describing these values as SNM statistics.

### 7. Post-layout Verification

Post-layout simulation uses the Quantus QRC-extracted view to account for layout parasitics.

The documented timing changes are small for `tprf` and larger for `tpfr`, illustrating why extracted-layout verification is important even when the schematic simulation is correct.

## Future Work

Potential extensions include:

2. **Peripheral Circuits:** Implement a row decoder, column multiplexer, precharge circuit, sense amplifier, and write driver.
